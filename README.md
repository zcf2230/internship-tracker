# 金融实习网申通

2027 寒假实习（+日常/远程/PTA/暑期）网申时间一站式查询站。静态网页，零依赖，部署在 GitHub Pages。

**线上地址**：https://zcf2230.github.io/internship-tracker/

## 功能

- **公司库**：1064 家机构的网申批次、用人要求、笔试面试流程、薪资食宿、留用情况、官网直达链接
- **「小而美公司」分类（596 家）**：体量不大但在细分领域有口碑的机构 —— 量化私募、精品投行/FA、中小券商研究所、精品咨询、评级、消费金融、融资租赁、小而美银行、保险与资管等 16 个细分；每家列出**主营方向 / 适合投递的岗位 / 体量量级 / 投递入口**
- **倒计时提醒**：按往年时间推算今年窗口，自动标注「预计开放中 / N 天后开放 / 已截止」，紧急高亮
- **时间轴视图**：2026.09 – 2027.03 全部网申窗口铺在一条时间线上
- **投递进度**：每家公司可标记 未投递→网申→笔试→面试→Offer/放弃，数据存本机浏览器
- **多条件筛选**：行业、城市、批次、本科可投、是否有笔试、杭州相关、投递进度
- **渠道与内推**：官方招聘公众号、权威信息平台、内推机制说明
- **笔面试攻略**：券商 / 公募PE-VC / 银行 / 四大 / 咨询PTA / 大厂数据岗 六类攻略

## 数据管线

明文源数据（**都不进仓库**，`.gitignore` 里排除）

```
tools/raw/*.json          ← 手工/调研产出的原始数据（brokers / funds / banks / big4 / dachang / region / …）
tools/raw/smallbeauty.json ← ⭐「小而美公司」596 家，由下面的脚本生成
tools/sbc-src.txt          ← ⭐「小而美公司」人工维护源文件（管道分隔，比 JSON 好改）
tools/auth.txt             ← 登录账号密码（加密用）
```

三步构建：

```bash
node tools/build-smallbeauty.js   # sbc-src.txt -> tools/raw/smallbeauty.json（仅「小而美公司」）
node tools/build-more.js          # more-src-*.txt -> tools/raw/more.json（原有 7 分类扩充）
node tools/verify-links.js        # ⭐ 实测官网域名（link-candidates-*.txt -> tools/links.json）
node tools/verify-links-render.js # ⭐ 第二轮：对 SPA / 被 WAF 拦的候选，用 Edge 无头渲染后复验
node tools/build-data.js          # raw/*.json -> tools/data.json（合并 + 去重 + 双向打标签 + 套用实测链接）
node tools/encrypt-data.js        # data.json -> js/data.enc.js（**先 gzip 再 AES-256-GCM**，见下）
node tools/check-data.js          # 自检：解密 + 核对条数与字段完整性 + 直链覆盖率 + 加密包体积守卫（无依赖）
node tools/test-decrypt.js        # 自检：用与浏览器相同的 WebCrypto+DecompressionStream 走一遍解密链路（无依赖）
node tools/ci-check-links.js      # 每日官网链接巡检（GitHub Actions 跑，也可本地手动跑；无依赖）
```

### 官网直链是怎么来的（tools/verify-links.js）

数据里的 `applyLink` 有两种来源：原作者人工整理的，以及本工具**实测验证**的。

1. 在 `tools/link-candidates-*.txt` 里写候选域名：
   `公司名 | 页面关键词 | 候选域名1 | 候选域名2`
2. `node tools/verify-links.js` —— 逐个实测，**必须「HTTP 200」且「页面正文出现关键词」才算通过**，
   避免认到同名或蹭名的站点；通过的写进 `tools/links.json`（明文，已 gitignore）。
   已通过的会缓存跳过，要全量重测加 `--force`。
3. `node tools/verify-links-render.js` —— 对「能打开但首屏 HTML 里没有公司名」的（SPA 站点）
   和「被 WAF 拦（403/412）」的，用 Edge 无头渲染后再搜一次关键词。
4. `build-data.js` 最后把 `links.json` **覆盖**到 `applyLink` 上——既用来补原来没链接的机构，
   也用来修失效的旧链接。
5. 实在测不出正确域名的机构，就**保持只有「🔍 搜官方入口」按钮**（跳必应搜官方招聘入口），不猜、不写错。

> ⚠️ 改完 `tools/data.json` **必须重跑 `encrypt-data.js`**，否则网页上是旧数据（`check-data.js` 会帮你发现）。

### 为什么要「先压缩再加密」（启动速度的关键）

AES-GCM 的密文是伪随机的、**完全不可压缩**，所以顺序错一步，体积就差近十倍：

```
❌ 明文 620KB → 加密 620KB → base64 830KB      （HTTP 层也压不动，下载 ≈ 1280KB）
✅ 明文 620KB → gzip 96KB → 加密 96KB → base64 128KB
```

1064 家机构时，老管线产物 **1196KB**。实测国内直连 GitHub Pages 大约只有 20–65 KB/s，
等于**每次打开本站都要先下 20 秒左右**，界面才会出来。改成先 gzip 之后产物 **128KB**，
下载降到 2–6 秒；浏览器端用原生的 `DecompressionStream("gzip")` 解压，不需要任何第三方库。

`tools/check-data.js` 里有一条**体积守卫**（加密包必须 < 300KB），
以后谁把管线改回「直接加密」会立刻报错。

**前端还有一处配套优化**：5 个页签不再在开机时一次性全渲染。
「投递进度」1064 张看板卡、「时间轴」1712 个色块、渠道与攻略页都不在首屏，
原来却要一并渲染（实测多花约 400ms、多 7000+ 个 DOM 节点）。现在切过去才渲染（`ensureTab`），
切回来直接复用。任何改动页签数据的地方调 `invalidateTab()` 标脏即可。

### 搜索/筛选为什么原来会卡（以及怎么修的）

症状：在搜索框里敲一个字，列表要顿一下；清空搜索恢复全量时最明显。
用真实 Chromium + CPU 降速 4 倍（约等于中端手机/老笔记本）量出来是 **3.5 秒才出现画面、5 秒才画完**。
四个原因叠在一起：

| 原因 | 说明 | 修法 |
|---|---|---|
| 每敲一个字都重算上万次状态 | `companyStatus()` 要构造 Date、解析批次时间；一次渲染里被调用「筛选 1064 次 + 排序每次比较 2 次 + 渲染 1064 次」约 1.2 万次。更糟的是 `matchCompany()` 里那句是**算了不用的死代码** | 删掉死代码；状态按 id 缓存（`statusOf`），一次会话只算一次 |
| 每个字都重拼 1064 家的可搜文本 | `[name, major, skills…].join(" ").toLowerCase()` 每次输入约 1MB 字符串分配 | 按公司缓存小写可搜文本（`haystack`），查询串只转一次小写 |
| 一次写入上万 DOM 节点 | 1064 张卡 ≈ 2.8 万节点，一次性 `innerHTML` 要一口气做样式计算+布局+绘制 | 渐进渲染：先同步画 80 张（首帧立刻有内容），其余按帧分批补；完整 DOM 最终仍在（Ctrl+F 能搜到） |
| 屏幕外的卡片也在排版 | 列表是 `flex + gap`，追加内容会重排整列 | ① 列表改 `block + margin`（视觉不变）；② 卡片加 `content-visibility: auto` + 校准过的 `contain-intrinsic-size`，屏幕外的不参与排版绘制 |

其中**第 4 条收益最大**（单这一条就把「输入一个字」从 3.5 秒降到 0.3 秒）：

| 操作（CPU 降速 4x） | 改前 | 改后 |
|---|---|---|
| 输入「银」（298 家） | 3513ms 才出现画面 | **288~378ms** |
| 输入任意字 | 每个字都顿 | 桌面 1x 下 **29~63ms** |
| 清空 → 恢复 1064 家 | 4994ms 出现 / 11130ms 画完 | **245ms** 出现 / 1760ms 画完 |
| 切「时间轴」页签 | 4354ms | **1619ms** |

`content-visibility` 的注意点：`contain-intrinsic-size` 必须贴近真实平均高度，否则滚动条长度会明显偏大、
滚动时位置会跳。本项目实测桌面平均 234px、手机 446px（要减掉 32px 内边距填「内容盒」高度），
校准后高度偏差从 55% 降到 5%。改了卡片内边距/字号后要重新校准这两个值。

### 每日官网链接巡检（tools/ci-check-links.js）

**先回答成本：完全免费，全程 0 个 AI / API token。**
它不需要理解页面内容，只回答「这台服务器还回不回话」——一个纯 Node 脚本发 HTTP 请求、对比结果，
跑在 GitHub Actions 上（公开仓库 Actions 免费），提交结果用的是 Actions 内置的 `GITHUB_TOKEN`，
**不需要申请任何 API token**。每天消耗约 542 次 HTTP 请求 + 1 分钟 runner 时间。

链路：

```
GitHub Actions 每天 10:30（北京时间）
  → 解开 js/data.enc.js 拿到 542 条直链（凭据来自仓库 Secrets，加密存储）
  → 并发 10 逐条请求（12s 超时 × 2 次重试）
  → 与上一轮结果合并：连续失败天数累加
  → 写 js/link-status.json（只有公司 id + 失败天数 + 日期，无公司名无 URL，可进公开仓库）
  → 有变化才自动 commit
```

网页端会读这个文件：同一条官网**连续 3 天**连不上，卡片上会出现「⚠️ 链接可能失效」，
提示语写明"可能已失效，也可能只是对方限制了程序访问，点「搜官方入口」可交叉核对"；
只失败 1–2 天的记为 warn 继续观察，不会打扰页面。概览条会显示「上次链接巡检 X 天前」。

**首次配置（一次性）**：仓库 Settings → Secrets and variables → Actions → 新增两个 secret：

| 名 | 值 |
|---|---|
| `SITE_USER` | 站点登录账号 |
| `SITE_PASS` | 站点登录密码 |

不配置的话工作流会安静跳过（退出码 0），不会每天报错。也可以在 Actions 页面手动 Run workflow。

**判定标准故意保守**：任何 HTTP 状态码（含 403/412/429/500 这类 WAF 拦截）都算存活；
只有 DNS 失败 / 连接被拒 / TLS 失败 / 两次都超时才算「连不上」。
脚本对老式 TLS（`SSL_OP_LEGACY_SERVER_CONNECT`）、不合规响应头（`insecureHTTPParser`）
都做了宽容处理——实测本地 542 条里 539 条存活，剩 3 条是「对方限制了程序访问」
（麦肯锡需代理、东吴/浙能的 WAF 重置非浏览器连接），这类靠 3 天连败规则兜底，不急着下结论。

### 界面与版式（2026-10-17 改版）

改版方向是「期刊／日报式排版」，参考了 [aihot.news/daily](https://aihot.news/daily) 的版式思路，但**只借手法、不搬内容**：

| 手法 | 在本站的落地 |
|---|---|
| 暖纸底色 + 单一强调色 | `--bg: #faf8f5`（暖白）、`--blue: #176b75`（青绿，变量名沿用旧名以免全站重命名）。强调色只用在小面积：当前页签、链接、关键数字、官网按钮 |
| 报头式 header | 32px/900 的文字报头 + 字距放大的英文小标 + 右侧「今天／数据整理于／新鲜度」元信息，替代原来的深蓝渐变横幅 |
| 一行统计条 | 报头下方：`1064 家机构 / 8 个分类 / 12 家正在开放网申 / 542 条官网直链 / 405 条官网已实测`。「正在开放」按当天日期实时算 |
| 目录式分类 | 分类 chip 变成 `01 券商/投行 142`：序号 + 名称 + 家数，同时保留多选筛选能力 |
| **用细线分割代替白盒子** | 公司列表从「1064 个带阴影的白卡片」改成「行 + 发丝分割线」，仅在悬停时铺白底；左边缘 2px 竖线表示状态（开放中绿／即将开放金／紧急红） |
| 数字分节与等宽数字 | 状态、家数、月份等用 `tabular-nums`，日期区间用等宽字体，纵向对齐更整齐 |
| 克制的状态标示 | 状态从彩色实底 pill 改成「小圆点 + 文字」；默认的「未投递」压成中性灰（1064 行都亮着实心色会很吵） |
| 渐进铺垫的信息 | 图例折叠进 `<details>`，用不到时只占一行 |

改版**只动视觉层**（`css/style.css` 为主，`index.html` 加了报头统计条与 `<details>` 图例，`js/app.js` 加了
`renderStatStrip` / `renderFreshness` 与分类 chip 的家数），功能逻辑、字段、渲染流程均未改变；
60 项功能自检在改版后仍全部通过。

⚠️ 改版后卡片高度变化，`contain-intrinsic-size` 已按新高度重新校准（桌面 182px 内容盒 = 实际 217px、
手机 366px = 实际 397px），滚动高度偏差从 7% 降到 0%。**再改卡片内边距/字号，必须重新校准这两个值。**

### 「小而美公司」怎么维护

1. 编辑 `tools/sbc-src.txt`，每行一家：
   `id | 公司名 | 细分分类 | 城市 | 规模量级 | 主营业务 | 适合投递方向 | 备注`
2. 跑 `node tools/build-smallbeauty.js`（会校验列数、细分分类、id 唯一）。
3. 再跑 `build-data.js` + `encrypt-data.js`。

**合并规则**（`build-data.js` 里实现）：

1. 名单里与已有公司**重名的不会重复建卡**——保留原有条目（信息更完整），只在它身上加一个 tag「小而美公司」，
   筛选时两边都能命中。
2. **双向归属**：小而美条目也按细分领域挂上它天然所属的原分类标签（城商行→银行/保险/信托、
   中小券商→券商/投行、会计师事务所→四大/咨询…），所以点「银行/保险/信托」能筛到全部银行，不重复建卡。
   映射表见 `build-data.js` 的 `SB_SECONDARY`。

新增条目的「用人要求」等共性内容不在数据里逐条重复，而是按细分领域 / 主分类兜底：
「小而美公司」用 `js/app.js` 的 `SB_DEFAULTS`，原 7 分类的扩充用 `EXTRA_DEFAULTS`。
逐家拿到官方口径时，直接写进数据即可覆盖。

### 扩充原有 7 个分类怎么维护

编辑 `tools/more-src-1.txt`（券商 / 基金资管 / 银行保险信托 / 四大咨询）或 `tools/more-src-2.txt`
（大厂金融科技 / 上市公司 / 央国企），每行：

`id | 公司名 | 主分类 | 细分 | 城市 | 主营业务 | 适合投递方向 | 备注`

再跑 `node tools/build-more.js`（会校验列数、主分类、细分是否有批次预设、**是否与已有公司重名**）。
细分是新的时候，要在 `build-more.js` 的 `BATCHES` 里补一条批次预设（或给 `主分类|*` 兜底），否则脚本会报错。

## 如何自己更新数据

数据现在走上面的管线。历史写法（直接编辑 `js/data.js`）已废弃——该文件在 `.gitignore` 中，仓库只存密文 `js/data.enc.js`。

1. `companies` 数组：每家公司一个对象。批次时间写模糊时间即可（如 `"约10月中旬"`），网站会自动换算成倒计时；写 `"全年滚动"` 则标记为常年招聘。
2. `channels` / `guides`：内推渠道与攻略文本。
3. 改完推送到 GitHub，几分钟后线上自动生效（GitHub Pages 部署）。

### 卡片上的两个标记分别是什么意思

一个笼统的「可信度低」把两件不同的事混在了一起，所以拆成两个独立标记：

| 标记 | 含义 |
|---|---|
| `✓ 官网已实测` | 这家的官网链接是**程序实测过能访问**的（HTTP 200 且页面出现公司名），实测日期见卡片提示。共 405 家 |
| `来源：官方公告` / `公开报道` / `规律推算` | 说明该公司的**网申时间与用人要求**是从哪儿来的。绝大多数中小机构不单独发公告，只能按同类机构往年规律推算——这是这类数据的固有性质，不代表这家公司本身不可靠 |

筛选区有图例直接解释这两列标记；详情弹窗底部会写清楚这家具体是哪种情况、官网有没有实测过。
